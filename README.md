# plugin-link

A generic [LinkML](https://linkml.io/) ERD viewer built with [SvelteKit](https://svelte.dev/docs/kit) and [Svelte Flow](https://svelteflow.dev/).

Upload any LinkML schema YAML file and explore it as an interactive entity-relationship diagram. Nodes are collapsible table cards; FK and ETL edges are the relationships reconciled off-client by the single LinkML producer.

Defaults to the fully merged [OMOP CDM](https://ohdsi.github.io/CommonDataModel/) v5.4 schema (37 classes with 42 foreign-key edges). Also includes the **SEIN** schema — a merged HiX staging + OMOP CDM subset with slot-level ETL mappings.

The app ships as both a **web SPA** (hosted on GitHub Pages) and a **native desktop app** built with [Tauri v2](https://tauri.app).

## Semantic authority — one producer, native pipeline

There is exactly one LinkML implementation: `produce.py` (pinned Python `linkml` 1.11.1 + `SchemaView`), invoked by the **native Vite pipeline** (`vite.config.ts`). It runs **off-client** and emits a deterministic JSON artefact. The browser never parses LinkML.

| Input mode | Path |
|---|---|
| **Bundled** | `static/reconciled/<name>.json` — generated by the Vite plugin on dev-server start and on build, then fetched and projected into the viewer |
| **Uploaded / hand-edited** | `POST /reconcile` — served by the Vite plugin's native dev-server middleware, running the *same* `produce.py`, returning the *same* artefact shape |

The bundled schemas are a pipeline output, not a hand-committed artefact set. Uploads and live editor edits are served natively in dev by the Vite plugin (`/reconcile`); `VITE_RECONCILE_URL` can point the client at an off-origin boundary. Production static export has no server hook; there is no in-browser fallback.

The plugin invokes the producer as `uv run --with linkml==1.11.1 --python 3.12 produce.py --all`; the reconciled artefacts land in `static/reconciled/`.

### Build, dev, and preview timing

- **`bun run build`** — `buildStart` *awaits* the producer before the bundle is emitted, so a producer failure fails the build with its own error and every `static/reconciled/*.json` artefact exists before `static/` is copied.
- **`bun run dev`** — generation is started off the critical path (dev-server availability does not wait on a cold `uv` toolchain provision); the viewer's artefact fetch retries (dev only, bounded) until the output is written.
- **`bun run preview`** — serves the already-built output. It deliberately mirrors the production static export: no generation and no `/reconcile` endpoint. A missing `build/reconciled/` produces a clear warning; the fix is to rebuild.

### Deployment boundary (production uploads)

The deployed app is a static SPA with **no server runtime**, so `POST /reconcile`
exists only in the Vite dev server. For uploaded / hand-edited schemas in
production, point the client at an off-origin reconciliation boundary with
`VITE_RECONCILE_URL`; there is no in-browser fallback and no new boundary is
invented in this repo.

## Features

- Drag-and-drop upload of any `.yaml` / `.yml` LinkML schema (reconciled through the producer service)
- **Schema YAML editor** — live CodeMirror 6 editor with syntax highlighting; edits are validated for YAML syntax and re-reconciled through the producer service (500ms debounce). It does not parse LinkML in the browser.
- **In-browser group color editor** — edit group labels and colors live without touching any files
- Auto-layout via [Dagre](https://github.com/dagrejs/dagre) or [ELK](https://eclipse.dev/elk/) (layered algorithm), switchable at runtime
- Left-side **group legend** sidebar — shown automatically when the schema has group-annotated classes; lists color swatches, slot row icon key, and edge type legend
- **Group-colored node headers** — each class's header is colored by its group annotation (configured in `static/group-config.yaml`)
- **ETL mapping badges** — slots with `exact_mappings` show the target column as an indigo italic badge, with the full mapping list on hover
- **ETL edges** — dashed indigo arrows drawn to the mapping's named target column (e.g. HiX → OMOP)
- Collapsible table nodes (click the header)
- Top-bar search with keyboard navigation and canvas pan-to-node
- MiniMap with group-aware node coloring

## Groups

Classes in a LinkML schema can carry a `group` annotation. When present, the node header is colored according to the group's entry in `static/group-config.yaml`, and the **group legend** sidebar appears automatically.

`annotations.group` is the canonical annotation. There is no `domain` alias — a `domain` annotation is ignored by the viewer.

### Annotating a class

Use the **compact annotation form** (a plain scalar value):

```yaml
classes:
  Person:
    annotations:
      group: clinical
    attributes:
      person_id:
        identifier: true
```

The LinkML metamodel also allows an expanded `{tag, value}` form, but the compact form is preferred and is what the included schemas (`sein.yaml`, `hix.yaml`) use:

```yaml
# expanded form — verbose, avoid
annotations:
  group:
    tag: group
    value: clinical
```

The parser accepts both forms.

### Configuring group colors

Edit `static/group-config.yaml` to add or change groups — no TypeScript changes required:

```yaml
groups:
  - name: clinical
    label: Clinical
    color: "#2563eb"
    text_color: "#ffffff"
  - name: hix
    label: HiX Source
    color: "#f59e0b"
    text_color: "#ffffff"
  - name: default
    label: Other
    color: "#475569"
    text_color: "#ffffff"
```

The `default` entry is the fallback color for classes whose group value does not match any named entry. It is not shown in the legend swatch list.

## ETL mappings

Slots can declare `exact_mappings` to record cross-schema column mappings (e.g. from a HiX staging column to an OMOP CDM column):

```yaml
attributes:
  patient_number:
    exact_mappings:
      - omop_cdm54:Person.person_source_value
```

The first mapping is shown as an indigo italic badge in the slot row (prefix stripped). Hover over it to see all mappings.

When both source and target classes are present in the schema, a **dashed indigo ETL edge** is drawn between them on the canvas.

## In-browser editors

Two slide-in panels are accessible from the top bar:

- **`</> Schema`** — opens a CodeMirror 6 YAML editor pre-loaded with the current schema. Edits are validated for YAML syntax (500ms debounce); valid text replaces the active workspace file and is re-reconciled through the producer service. Parse errors are shown in a red bar; the canvas is not updated until the YAML is valid.
- **`◎ Groups`** — opens a group color-picker form. Each row has a name, label, background color, and text color. Changes are applied to all node headers and the legend immediately.

## Included schemas

| File | Description |
|---|---|
| `static/omop_cdm.yaml` | OMOP CDM v5.4 — fully merged, 13 879 lines, default schema |
| `static/sein.yaml` | SEIN — 13 HiX staging + 17 OMOP classes, with `exact_mappings` and group annotations |
| `static/hix.yaml` | HiX staging classes only (13 classes) |
| `static/sein-omop.yaml` | OMOP CDM subset used by SEIN (17 classes) |

Reconciled artefacts (the viewer's source of truth) are generated into `static/reconciled/` by the Vite pipeline and are not committed.

### Layout-experimentation handoff (C1)

The former `tooling/layout-benchmark/` harness was deleted along with the
parity/witness benchmark tooling; only its prior output remains under
`test-results/` (gitignored). Resuming C1 — layout-engine experimentation —
requires re-creating a benchmark driver as an **additive** task. No such tooling
is created here.
